# Dashboard demo guide

Use a preview or local fixture database for any changes shown in the demo.

## Stakeholder demo · 5 minutes

| Time | Show |
| --- | --- |
| 0–1 min | Open the dashboard and explain the paid and pending totals. |
| 1–2 min | Search for a customer and open their invoices. |
| 2–4 min | Create a sample invoice, change its status to paid, and show the updated overview. |
| 4–5 min | Show where to correct an error on a form, then invite questions. |

## Technical demo · 5 minutes

| Time | Show |
| --- | --- |
| 0–1 min | Identify the browser, server, data access, and PostgreSQL layers in the architecture diagram. |
| 1–2 min | Trace an invoice submission through validation, authorization, write, and refresh. |
| 2–3 min | Show how migrations and fixture data initialise the isolated Supabase database. |
| 3–4 min | Run the Vitest suite and describe the Playwright and accessibility checks. |
| 4–5 min | Open the required GitHub checks and explain the teacher approval gate. |

## Näyttö — Finnish in Context

1. Open the practice area and explain whom it is for.
2. Choose an incorrect form and show the explanation. Complete the full lesson and restart.
3. Wait for the offline indicator, disconnect the browser, then reload and answer another question.
4. Show the viewport on a phone and ask the teacher to compare the flow and vocabulary against the [acceptance criteria](finnish-practice.md).
5. Record feedback and acceptance on [the feature issue](https://github.com/kiteekk2026/David-test/issues/39).
